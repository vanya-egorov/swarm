# swarm

Прототип управления дронами через MAVLink. Поддерживает телеметрию трёх Iris, проверки моторов, маршрут одного аппарата и общий ограниченный взлёт/посадку группы. Алгоритм совместного обследования ещё не реализован.

## Запуск

Нужны Go, Webots и собранный ArduPilot SITL. Откройте мир Iris из примеров ArduPilot в Webots и запустите моделирование. Затем в каталоге проекта выполните:

```sh
make start
```

Для остановки SITL и Go из другого терминала:

```sh
make stop
```

Webots остаётся открытым. Обычный запуск только принимает телеметрию и не отправляет полётные команды. Для тестов Go выполните `go test ./...`; Webots им не требуется.

## Где что находится

- `internal/vehicle` — состояние дрона и сценарии проверок, независимые от MAVLink.
- `internal/mavlink` — приём телеметрии и отправка команд автопилоту.
- `cmd/swarm` — запуск приложения.
- `scripts/` и `sim/` — запуск стенда и его параметры.

Стенд рассчитан на один или три Iris в Webots. По умолчанию запускатель ищет ArduPilot в локальных данных проекта; для другого расположения задайте `ARDUPILOT_DIR`.

## Проверки полёта в SITL

При открытом мире Iris в Webots и запущенном моделировании:

```sh
make arm-check     # arm/disarm без взлёта
make flight-check  # взлёт на 1,5 м и посадка
make route-check   # взлёт, квадрат 2×2 м, возврат к старту и посадка
```

Сценарии запускаются по одному вместо `make start`. Проверка маршрута использует четыре
точки со смещениями (север, восток): (2, 0), (2, 2), (0, 2), (0, 0) метров.
Пределы: высота 2,5 м, удаление от старта 5 м, ожидание каждой точки 25 секунд.
Достижение каждой точки проверяется по позиции, высоте и скорости, затем выполняется LAND.
При ошибке или Ctrl+C также запрашивается посадка, а телеметрия читается до завершения её проверки.

Логи: `projectData/run/logs/swarm.log` и `projectData/run/logs/sitl.log`.
Успешный маршрут содержит четыре события `waypoint reached` и событие `landed`.
Остановка из другого терминала — `make stop`, состояние запускателя — `make status`.
Обычный `make start` по-прежнему запускает только наблюдение.

Маршрут и совместный взлёт/посадка трёх Iris проверены в Webots, включая отмену группы в воздухе.
[Результаты полётов](projectData/docs/2026-10-22-flight-routes.md). Ближайшие этапы и критерии готовности — в [существующей дорожной карте](projectData/PROPOSAL.md#11-дорожная-карта-с-условиями-завершения-этапов).

## Качество кода

Нужен `golangci-lint` v2 (проверено с 2.6.1). Включены 25 линтеров: проверки ошибок,
контекстов, логирования, имён, комментариев, лишних преобразований и присваиваний.
Форматирование: gofmt, goimports и golines (120 символов).

```sh
make lint        # анализ ошибок и форматирования Go, синтаксис Bash
make fmt         # исправление форматирования и импортов
make check       # линтинг, тесты Go с проверкой гонок, тесты запускателя
```

## Подготовка стенда с тремя Iris

```sh
make swarm-world
```

Команда создаёт локальный проект Webots в `projectData/run/webots`, используя модель и
контроллер из `ARDUPILOT_DIR`. Откройте выведенный путь `iris-three.wbt` в Webots,
запустите моделирование, затем выполните:

```sh
make swarm-start
```

| Iris / instance | MAVLink system ID | UDP телеметрии | Порт контроллера Webots |
|---|---|---|---|
| 0 | 1 | 14560 | 9002 |
| 1 | 2 | 14570 | 9012 |
| 2 | 3 | 14580 | 9022 |

Модели разнесены на 12 м. Для каждого аппарата запускаются отдельные SITL и Go-монитор;
команды полёта при общем запуске не отправляются. Логи получают суффиксы `-I0`, `-I1`, `-I2`.
`make stop` останавливает весь стенд; при завершении любого дочернего процесса остальные
также останавливаются. Для SITL ограничено ожидание TERM, затем при необходимости выполняется KILL.
Исходники ArduPilot не меняются, Webots запускается пользователем.
Общий запуск и однодронные проверки используют один механизм остановки и запускаются по очереди.

Три Iris одновременно проверены в Webots: телеметрия, arm/disarm без взлёта и штатная
остановка. Повтор наземной проверки при открытом и перезагруженном мире:

```sh
make swarm-arm-check
# Только второй Iris (system ID 2); остальные два наблюдаются без команд:
CHECK_INSTANCE=1 make swarm-arm-check
```

Запускатель ожидает завершения всех выбранных проверок. Общий ограниченный полёт доступен
отдельной командой `make swarm-flight-check`. Результаты и границы проверки — в [протоколе](projectData/docs/2026-10-22-three-iris.md).

## Ограниченный полёт в мире трёх Iris

После перезагрузки мира `iris-three.wbt` и запуска моделирования:

```sh
make swarm-route-check   # только Iris 0 проходит квадрат, два остальных остаются на земле
make swarm-flight-check  # три Iris взлетают на 1,5 м, удерживаются 8 с и садятся
```

Запускайте сценарии по очереди. `make stop` во время полёта отменяет сценарий и оставляет
телеметрию активной до завершения попытки посадки. Групповой сценарий использует один
процесс Go с тремя MAVLink-приёмниками; его общий журнал — `projectData/run/logs/swarm-I0.log`.

Для группы требуется непересекающаяся область радиусом 2 м у каждого места старта
и минимальная дистанция 4 м. Потеря телеметрии, нарушение границ или отказ участника
отменяют остальные сценарии, каждый выполняет LAND и подтверждает посадку.
Это проверка одновременного полёта: маршруты группы и обход столкновений ещё не реализованы.

# swarm

Управление тремя Iris через MAVLink в Webots. Реализованы телеметрия, arm/disarm,
взлёт/посадка, маршрут одного дрона и совместный маршрут трёх дронов с ожиданием
всех участников на каждом этапе. Добавлено планирование покрытия прямоугольной территории:
разбиение между дронами, маршруты змейкой и распределённое исполнение задания.
Агенты обмениваются состояниями по UDP, автоматически выбирают лидера и заменяют его
при потере связи или неисправности. Добавлены лидар, сонары и локальный обход
препятствий внутри выделенной области.

[Сенсоры и автономный обход в основном мире](docs/obstacle-avoidance.md).

## Планирование покрытия территории

Пакет `internal/drone/coverageMap` работает без Webots и MAVLink. Область задаётся
прямоугольником в метрах в общей системе север/восток. `Decompose` делит её на равные
полосы без пропусков и пересечения внутренностей, назначая их переданным system ID
в порядке списка. `GenerateRoute` строит змейку для одной области, `Plan` объединяет
разбиение и построение маршрутов:

```go
area := coverageMap.Area{
    Min: coverageMap.Point{NorthM: 0, EastM: 0},
    Max: coverageMap.Point{NorthM: 30, EastM: 18},
}
config := coverageMap.DefaultConfig()
config.SwathWidthM = 2
config.LaneSpacingM = 1.5
assignments, err := coverageMap.Plan(area, []uint8{1, 2, 3}, config)
if err != nil {
    return err
}
// assignments[i]: SystemID, Area, Waypoints в общей системе карты.
```

Импорт пакета: `github.com/vanya-egorov/swarm/internal/drone/coverageMap`.
При `NorthSouth` проходы идут вдоль северной оси, полосы распределяются по восточной;
`EastWest` меняет оси местами. Каждый дрон получает одинаковую площадь; число точек
и время полёта могут различаться. План детерминирован, поддерживает 1–255 уникальных
ненулевых system ID и ограничен 100 000 точек суммарно. Невалидные координаты,
слишком мелкое разбиение и превышение лимита возвращают ошибку без частичного плана.

`SwathWidthM` — сторона гарантированного квадратного пятна обзора на земле на выбранной
высоте; её задаёт вызывающий код по характеристикам камеры. Шаг проходов должен быть
положительным и не больше этой ширины. Проходы равномерно распределяются поперёк полосы,
с фактическим шагом не больше заданного. Отступы от краёв учитывают половину пятна обзора:
при движении по прямым между точками покрываются также края и углы. Малые области
могут требовать одного прохода или одной точки. Маршруты строго внутри своих подобластей,
включая развороты; пятна обзора соседей могут перекрываться.

Перед использованием в существующем исполнителе вызовите
`assignment.WaypointsFrom(launch)`, где `launch` — место старта этого дрона в общей
системе карты. Полученные `route.Waypoint` заданы относительно его старта; высота
остаётся высотой над его home. Их можно преобразовать в WGS84 через `route.TargetsFrom`
с географическими координатами этого же старта. Исходный план при этом не меняется.

Функция `Plan` не запускает полёт. Для исполнения добавлены `PrepareMission` и
`MissionRunner`: индивидуальные маршруты связываются с сетевыми барьерами и подтверждённой
посадкой. [Конфигурация, запуск и протокол координации](docs/distributed-coverage.md).

Исполнитель проверяет `RouteCheckConfig.Validate()`: допускаются до 20 точек,
высоту 0,8–2 м и ограниченную дистанцию от старта. `RunGroupRouteCheck` пока исполняет
одинаковые смещения всех участников. Распределённое покрытие запускается отдельно через
`--coverage-mission`: каждый процесс управляет своим дроном. До первого взлёта нужны
все участники; продолжение после отказа требует исправного большинства. Потерянные области
автоматически не переназначаются, а итоговое покрытие отмечается как неполное.
Произвольные многоугольники, рельеф и возврат к старту пока не поддерживаются.

## Совместный полёт трёх дронов

Нужны Go, Webots и локальный клон ArduPilot с зависимостями сборки SITL.
По умолчанию клон находится в `projectData/ardupilot`; другое расположение задаётся
через `ARDUPILOT_DIR`. Для Python сборки используется `.venv/bin/python3` клона,
если он существует, либо текущий Python. Можно задать `SITL_PYTHON` и `SITL_JOBS`.

```sh
make sitl-build   # один раз: собрать SITL с исправлением часов адаптера Webots
make village-deps  # установить зависимости экспорта карты
make village-world # подготовить мир с деревней
```

Основной сценарий проекта — совместный полёт трёх Iris на карте деревни. Подготовьте
и откройте `projectData/run/webots/worlds/village.wbt` (подробнее ниже), включите
моделирование, затем выполните `make village-route-check`. Три Iris одновременно
взлетают на 1,5 м, проходят квадрат 2×2 м относительно своих мест старта и садятся.
Смещения точек (север, восток): (2, 0), (2, 2), (0, 2), (0, 0) м.
Следующая точка назначается только после устойчивого прибытия всех трёх аппаратов;
быстрые участники продолжают удерживать текущую цель, пока остальные подходят.
Успех: четыре `group waypoint reached`, по четыре `waypoint reached` для каждого ID,
три `landed`, итоговое `group landed` и код завершения 0.

Перед каждым новым прогоном перезагрузите мир Webots, не сохраняя изменённые положения
дронов. Если положение после полёта или аварии уже сохранено, выполните `make village-world`
и заново откройте созданный файл. Для отмены во время полёта:

```sh
make stop
```

Приложение отменяет маршрут, запрашивает LAND у всех участников параллельно и продолжает
принимать телеметрию до завершения проверок посадки. Отмена сохраняется как причина
ошибки в журнале Go; обработка `make stop` самим запускателем завершается штатно.
Webots остаётся открытым. Состояние запускателя: `make status`.

## Карта с деревьями и декором

Добавлен перенос готового проекта карты в Webots без запуска Unity:

```sh
make village-deps
make village-world
```

Основной мир — `projectData/run/webots/worlds/village.wbt` размером 1,5×1,5 км.
Дома и две крупные модели гор исключены; деревья, трава, обычные камни и остальной
декор сохранены. После открытия мира и запуска моделирования — `make village-route-check`.

[Подготовка карты, оптимизация и проверки](docs/village-webots.md).

## Ограничения группового сценария

| Параметр | Совместный маршрут | Взлёт/посадка группы |
|---|---|---|
| Высота цели / порог отмены | 1,5 / 2,5 м | 1,5 / 2,5 м |
| Радиус области у каждого старта | 3,5 м | 2 м |
| Минимальная горизонтальная дистанция | 4 м | 4 м |
| Предельный возраст телеметрии | 5 с | 5 с |
| Ожидание одной точки | 25 с | — |

До команд проверяются все участники, уникальность ID, наземное состояние,
маршрут и непересекающиеся области: расстояние стартов должно быть не меньше
двух радиусов плюс минимальная дистанция. В мире старты разнесены на 12 м.
При потере телеметрии, выходе за границы или отказе участника отменяется вся группа.
Посадки имеют независимые контексты: ошибка одной не отменяет остальные попытки.
Порог отмены запускает LAND и не является физическим ограничителем траектории.

Это синхронное прохождение одинаковых смещений в раздельных областях.
Динамическое удержание формации и планирование пересекающихся маршрутов не реализованы.

## Исправление часов SITL

У используемой ревизии ArduPilot адаптер `SIM_Webots_Python` при задержке UDP может
повторно прибавить всё время мира к часам SITL. В прогоне трёх Iris это вызвало
скачок времени и аварийное завершение одного автопилота. Патч проекта
`sim/ardupilot/patches/webots-clock.patch` убирает этот сброс и задаёт корректную
начальную временную базу, включая перезагрузку мира. На macOS
сборка отключает chained fixups для совместимости с упакованной структурой FWVersion.

`make sitl-build` временно применяет патч для сборки, восстанавливает исходный файл
ArduPilot и сохраняет отдельный бинарный файл `projectData/run/bin/arducopter-webots`.
Запускатель предпочитает его обычному SITL. Явный `SITL_BIN` имеет приоритет.
После обновления ArduPilot повторите сборку; несовместимый патч отклоняется до изменения клона.
При ошибке сборки исходный файл также восстанавливается. Если другой процесс изменил
его во время сборки, новая редакция сохраняется, а исходная копия остаётся в
`.swarm-sitl-source-backup/` внутри клона.

## Другие сценарии

### Панель управления

Для запуска сценариев карты деревни и просмотра журналов в браузере выполните:

```sh
make console
```

Страница берётся из локального `ui/dist/index.html`. Каталог `ui/` исключён из Git,
поэтому панель доступна в checkout, где отдельно подготовлена сборка интерфейса.
Откройте `http://127.0.0.1:8765`. Панель управляет актуальными сценариями карты деревни: мониторинг трёх Iris,
проверка arm/disarm и совместный маршрут с посадкой. Остановка отправляет
штатную команду отмены существующему стенду; Webots остаётся открытым. Перед полётным
сценарием откройте мир в Webots и включите симуляцию. MAVLink и Webots остаются
основой симуляции, интерфейс только запускает и показывает состояние devstack.

На macOS, если Webots сообщает `Unable to find the 'python' executable`, укажите
интерпретатор в `Webots → Preferences… → Python command`, например
`/Users/vny/.pyenv/versions/3.12.0/bin/python`, затем перезагрузите мир. В панели
дождитесь статуса `MAVLINK · 3 / 3`; пока отображается `ОЖИДАЕМ MAVLINK`, контроллеры
Webots ещё не подключились и полётный сценарий запускать не следует.

| Команда | Действие |
|---|---|
| `make swarm-start` | Три пассивных монитора телеметрии |
| `make swarm-arm-check` | Arm/disarm всех трёх без взлёта |
| `CHECK_INSTANCE=1 make swarm-arm-check` | Проверка только ID 2 при двух пассивных мониторах |
| `make swarm-flight-check` | Общий взлёт, удержание 8 с и посадка |
| `make swarm-route-check` | Квадрат только Iris 0; остальные на земле |
| `make start` | Пассивная телеметрия одного Iris |
| `make arm-check` | Arm/disarm одного Iris |
| `make flight-check` | Взлёт и посадка одного Iris |
| `make route-check` | Квадрат одного Iris |

Однодронные команды требуют соответствующий мир Iris из примеров ArduPilot.
Все сценарии запускаются по очереди. Полётные CLI-флаги работают только с loopback-адресами.

| Iris / instance | MAVLink system ID | UDP телеметрии | Порт контроллера Webots |
|---|---|---|---|
| 0 | 1 | 14560 | 9002 |
| 1 | 2 | 14570 | 9012 |
| 2 | 3 | 14580 | 9022 |

Групповые полёты используют один процесс Go с тремя приёмниками.
Общий журнал — `projectData/run/logs/swarm-I0.log`, журналы SITL — `sitl-I0.log` … `sitl-I2.log`.
В других режимах монитор каждого Iris пишет `swarm-I0.log` … `swarm-I2.log`.
Сбой дочернего процесса останавливает стенд; время завершения Go и SITL ограничено.
Если автопилот или весь симулятор перестал работать, подтверждение посадки может быть
невозможно — в этом случае журнал сохраняет ошибку, успех не сообщается.

## Структура кода

- `cmd/swarm/main.go` — единственная точка входа: создаёт логгер и обрабатывает сигналы.
- `internal/cli` — параметры запуска и выбор сценария; `group.go` запускает групповые проверки.
- `internal/drone/telemetry` — данные и приём телеметрии.
- `internal/drone/flight` — проверки и состояние полёта одного аппарата.
- `internal/drone/route` — маршрут одного аппарата.
- `internal/drone/group` — совместный полёт и маршрут группы.
- `internal/drone/coordinates` — координаты и геометрические расчёты.
- `internal/drone/coverageMap` — разбиение территории, назначение дронам и маршруты покрытия змейкой.
- `internal/drone/coordination` — UDP-обмен состояниями, долговечные голоса, выбор лидера и барьеры задания.
- `internal/drone/sensors` — атомарные кадры лидара/сонаров и проверяемый UDP-приёмник.
- `internal/drone/navigation` — карта наблюдённого пространства и локальное перепланирование движения.
- `internal/mavlink/command` и `internal/mavlink/telemetry` — команды и телеметрия MAVLink.
- `scripts/devstack/` — конфигурация, запуск, наблюдение и остановка процессов стенда.
- `sim/` — мир, параметры и воспроизводимый патч SITL.

## Проверки

Нужен `golangci-lint` v2. Форматирование: gofmt, goimports, golines (120 символов).

```sh
make lint        # анализ Go, форматирование и синтаксис всех частей запускателя
make fmt         # форматирование Go
make test        # тесты Go без Webots
make check       # линтер, Go с проверкой гонок, Python-тесты запускателя и сборки
```

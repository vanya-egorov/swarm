# Карта для Webots

Карта переносится из `проект_карта_деревни/Assets` без запуска или установки Unity.
Исходный проект не изменяется. Для экспорта не нужны `Library` и другие кэши Unity.

## Состав и размер

Из сцены исключены четыре модели домов и крупные модели
`PP_Forest_Mountain_Moss_01/02`. Деревья, трава, обычные камни, цветы, грибы и мосты сохранены.
Это исключает 239 экземпляров: 99 домов и 140 крупных моделей гор.
Рельеф земли остаётся исходным.

По умолчанию вырезается участок **1500×1500 м** из исходных 3000×3000 м:
каждая сторона уменьшена вдвое, площадь — вчетверо. Размеры объектов и их плотность
сохраняются: геометрия не сжимается, деревья не прореживаются.
В основном мире — **6774 объекта** и сетка рельефа **257×257**.
Дополнительно создаётся небольшой полётный участок около 240×240 м.

Графика объектов использует общие Mesh и материалы через DEF/USE.
Коллизии неподвижных объектов сгруппированы в пространственные участки по 100 м.
Это сохраняет столкновения на всей экспортированной территории, не создавая отдельный
корневой Solid для каждого растения.

## Подготовка

Нужны Python 3.12+, Webots, Go и собранный SITL проекта. Зависимости конвертера
устанавливаются отдельно от системного Python:

```sh
make village-deps
make village-world
```

Другой исходный проект или размер:

```sh
VILLAGE_SOURCE=/path/to/project VILLAGE_MAP_SIZE=1500 make village-world
```

Результаты находятся в `projectData/run/webots/`:

- `worlds/village.wbt` — основной мир 1,5×1,5 км с тремя Iris.
- `worlds/village-flight.wbt` — небольшой участок для быстрых полётных проверок.
- `protos/village/` — преобразованные модели, материалы и текстуры.
- `village-manifest.json` — размеры, фильтр, число объектов, координаты стартов и SHA-256 входных файлов.
- `village-flight.parm` — параметры полёта, собранные из базового профиля и дополнения карты.

Исходные деревья и другие модели переводятся из FBX в OBJ с учётом единиц FBX,
масштаба и поворотов сохранённой сцены. Рельеф извлекается непосредственно из TerrainData.
Его текстура запекается из пяти исходных слоёв и их карт смешивания.

## Просмотр и полёт

Откройте `projectData/run/webots/worlds/village.wbt` в Webots.
Включите моделирование и запустите:

```sh
make village-route-check
```

Три Iris выполняют прежний совместный квадрат 2×2 м, возвращаются и садятся.
Для телеметрии без команд полёта — `make swarm-start`; для отмены — `make stop`.
Перед новым прогоном перезагрузите мир, не сохраняя изменившиеся положения дронов.
`make village-world` восстанавливает исходное состояние экспортированных миров.

Границы сценария не расширены до размеров карты: цель высоты — 1,5 м,
порог отмены — 2,5 м, радиус каждого участника — 3,5 м, минимальная дистанция — 4 м.
Полёты по всей территории и обход препятствий пока не реализованы.

Профиль карты задаёт начальную тягу зависания по параметрам Iris,
плавный рост тяги при взлёте и ограниченную вертикальную скорость.
При подготовке мира поиск стартов выбирает ровный участок без препятствий;
три площадки расположены с интервалом 12 м.

Перед включением моторов Go наблюдает наземное состояние не менее 20 секунд
по реальным часам и по часам автопилота. Поэтому замедленная симуляция не сокращает
время проверки IMU. Ожидание ограничено 100 реальными секундами; перезапуск часов
автопилота прекращает запуск.

## Автоматические проверки

```sh
make test-village                         # координаты, фильтр, рельеф, материалы
make village-validate                     # небольшой участок внутри Webots
python3 scripts/validate_village.py --full # основной мир, замер загрузки и изображения
make village-flight-check                 # отдельный Webots + три SITL, весь маршрут
make check                                # основные проверки проекта
```

Пакетные проверки используют отдельные порты и не требуют управления интерфейсом.
`village-flight-check` по умолчанию проверяет основной мир; для небольшого участка:

```sh
python3 scripts/check_village_flight.py --world village-flight
```

Полётная проверка дожидается посадки Go перед остановкой автопилотов и физики.
Отчёты, изображения и журналы сохраняются в `projectData/run/verification/village/`.
`loadSeconds` измеряется от запуска процесса Webots до готовности контроллера проверки;
`validationSeconds` дополнительно включает шаги физики, изображения и завершение процесса.

## Границы переноса

Конвертер рассчитан на сохранённую статическую сцену этого проекта с одним TerrainData
и FBX-моделями. Неединичные родительские трансформации и отверстия в рельефе явно
отклоняются. Скрипт генератора леса не исполняется: переносится уже сохранённая расстановка.

Визуальные модели сохранены, коллизии деревьев и камней представлены консервативными
коробками. Мелкий декоративный подлесок не получает коллизий. Сложные эффекты URP,
анимации растений и динамическая вода не переносятся.
